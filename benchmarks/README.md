# 公网性能与协议评测归档

本目录保存2026-10-31对自建Java/Netty、frp 0.71.1、OpenSSH 8.9p1的评测依据。两轮测试均从实际公网链路获取数据，轮流使用服务器9090；使用SSH共同承载层和资源限额，不能当作各产品原生部署的极限性能。

**归档复核发现Windows测试客户端清理遗漏，历史阶段可能受残留JVM的资源占用和重连干扰。11个客户端已结束、脚本清理方式已修正，原始测量数据未回写。请先阅读[评测限制与归档复核](../docs/评测限制与归档复核.md)，不要将历史场景成绩作为严格性能排名。**

## 阅读顺序

1. **[多协议测试报告](20261031-protocols/多协议测试报告.md)**：后续补测发现的兼容性边界，应优先阅读。
2. **[首轮最终结论](20261031/最终结论.md)**、[首轮完整性能报告](20261031/性能比较报告.md)：仅针对TCP承载HTTP负载，不代表全协议成熟度。
3. **[归档清单与SHA-256](evidence-manifest.json)**：文件、大小、校验值和测试产物身份。

## 两轮数据的区别

| 数据集 | 覆盖范围 | 正式数据 | 补充依据 |
|---|---|---|---|
| `20261031` | TCP映射承载HTTP/1.1；短/长连接、1/4并发、64B/64KiB/1MiB | 54组，1,278次请求，0错误 | 公网直连参考、服务器采样、清理健康记录 |
| `20261031-protocols` | 19项共同TCP应用用例，加Java/frp原生UDP与HTTP/HTTPS路由 | 237组，1,149次操作，78次失败 | 配置复测135次、WS复测15次、WS阶段拆分18个会话、无隧道夹具校验91次 |

第二轮78次失败的构成为：两款半关闭各15次、自建UDP空报文15次、frp默认包长下的大UDP报文30次、frp WebSocket偶发超时1次、自建路由启动早期404共2次。后续复测单独保存，不覆盖失败记录。不同产品覆盖项不同，不能用总失败数直接排名。

## 校验与复现

```sh
# 只读验证所有已归档文件的SHA-256，不连接服务器
python benchmarks/archive_evidence.py --verify

# 验证第二轮矩阵、分组、夹具、资源记录的一致性，不重新跑流量
python benchmarks/20261031-protocols/validate_results.py
```

重新实测前，请先阅读[协议轮复现说明](20261031-protocols/README.md)。归档脚本包含本次目标IP和固定临时目录；换机器应先调整参数并审核清理脚本，不能直接把历史清理路径用于其他服务。首次性能轮脚本启动器位于`run_wan.py`，直接参考位于`run_direct.py`。

## 公开归档的边界

- 保留原始测量文件字节；`.gitattributes`禁用本目录的自动换行转换，使校验值跨平台一致。日志在结束残留客户端后固定归档；脚本和报告包含明确标注的事后修正。
- `cert.pem`仅为公开的、已过期或短期自签名测试证书，不包含私钥。`frpc.toml`/`frps.toml`中的临时令牌已替换为占位符。
- 不提供SSH登录密钥、测试私钥、有效令牌、known_hosts、本机依赖目录、第三方下载缓存、编译class目录。
- 被测JAR体积约2.64MiB，特例保留以支持精确产物核验；第三方frp请按版本从官方获取。
- 日志中的连接重置、预检失败和失败复测均保留，不删除不利结果。日志可能含测试主机地址、客户端ID和工作目录，属于本次评测环境记录。
