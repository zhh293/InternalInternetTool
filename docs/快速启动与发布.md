# 公网下载与快速启动

目标体验是“下载 → 解压 → 初始化 → 启动”，不需要在目标机器安装Maven或编译源码。

## 选择下载包

| 文件 | 适用机器 | 是否需要安装Java |
|---|---|---|
| `tunnel-linux-amd64.tar.gz` | Linux x86_64，Ubuntu 22.04或兼容系统 | 不需要，包含运行时 |
| `tunnel-linux-arm64.tar.gz` | Linux ARM64，Ubuntu 24.04或兼容系统 | 不需要，包含运行时 |
| `tunnel-windows-amd64.zip` | Windows x64 | 不需要，包含运行时 |
| `tunnel-java.zip` | Windows/Linux/macOS等 | 需要Java 11+ |

附带运行时的Linux包使用glibc，不是Alpine/musl原生包；其他平台可使用通用Java包。

发布渠道：[GitHub Releases](https://github.com/zhh293/InternalInternetTool/releases)。下面的URL是发布后的下载方式；首次草稿发布前，链接尚未生效。

## Linux服务端

以x86_64为例，下载和校验：

```sh
base=https://github.com/zhh293/InternalInternetTool/releases/latest/download
curl -fLO "$base/tunnel-linux-amd64.tar.gz"
curl -fLO "$base/tunnel-linux-amd64.tar.gz.sha256"
sha256sum -c tunnel-linux-amd64.tar.gz.sha256
tar xzf tunnel-linux-amd64.tar.gz
cd tunnel
./tunnel --version
```

首次初始化需要OpenSSL 1.1.1+，用于生成包含服务器IP或域名SAN的自签名证书。日常运行只需要包内运行时。Ubuntu缺少OpenSSL时可运行`sudo apt-get install openssl`。

```sh
# SERVER_IP换成实际公网IP或域名。--server不包含端口或https://。
./tunnel init-server --server SERVER_IP --public-port 9090
./tunnel server -c state/server.properties
```

初始化生成`state/server.properties`、`state/token`、`state/server.crt`、`state/server.key`，已有文件不会被覆盖。配置中的文件路径为绝对路径，移动整个目录后应修改这些路径。

云安全组和机器防火墙需允许TCP **7000、7001、9090**。7000是控制端口，7001是工作端口，9090是此示例公开入口；仅开放9090不足以让客户端直接连接。管理入口默认只绑定`127.0.0.1:8088`。

把**仅`token`和`server.crt`**通过SSH/SCP等可信渠道复制到客户端。`server.key`留在服务器，不应交给客户端；令牌不放进公网下载包。

## Windows客户端

在PowerShell下载并校验：

```powershell
$base = 'https://github.com/zhh293/InternalInternetTool/releases/latest/download'
Invoke-WebRequest "$base/tunnel-windows-amd64.zip" -OutFile tunnel-windows-amd64.zip
Invoke-WebRequest "$base/tunnel-windows-amd64.zip.sha256" -OutFile tunnel-windows-amd64.zip.sha256
$expected = ((Get-Content tunnel-windows-amd64.zip.sha256) -split '\s+')[0]
if ((Get-FileHash tunnel-windows-amd64.zip -Algorithm SHA256).Hash -ne $expected) { throw 'Checksum mismatch' }
Expand-Archive tunnel-windows-amd64.zip -DestinationPath .
Set-Location tunnel
```

把从服务器取得的`token`和`server.crt`放进当前`tunnel`目录；假设内网应用在`127.0.0.1:8080`：

```powershell
.\tunnel.cmd init-client --server SERVER_IP --public-port 9090 --local-port 8080
.\tunnel.cmd client -c state/client.properties
```

随后访问`http://SERVER_IP:9090`，即可访问客户端的8080服务。若8080上没有服务，应先启动自己的应用。

Linux/macOS客户端使用同样参数，把`.\tunnel.cmd`换成`./tunnel`。通用Java包若经ZIP工具解压丢失执行权限，先运行`chmod +x tunnel`。

## 命令和配置

```text
tunnel --help
tunnel /help
tunnel -h
tunnel help init-client
tunnel init-server --help
tunnel init-client --help
tunnel --version
tunnel server -c server.properties
tunnel client -c client.properties
tunnel init-server --server HOST [--dir state] [--public-port 9090]
tunnel init-client --server HOST [--dir state] [--public-port 9090] [--local-port 8080]
    [--local-host 127.0.0.1] [--client-id home-pc]
    [--token-file token] [--ca-file server.crt]
```

帮助入口支持`--help`、`-h`、`/help`、`help`；各子命令可用`命令 --help`或`help 命令`查看参数、默认值和示例，显示帮助不会启动服务或生成凭据。

也可直接运行`java -jar tunnel.jar --help`；原来的`java -cp ... dev.tunnel.Server/Client config`仍然支持。手工编写配置时，证书、令牌等相对路径仍基于启动时的工作目录。

启动器默认使用`-Xms16m -Xmx128m -XX:MaxDirectMemorySize=64m`，这不是进程总内存上限。需要调整时用`JAVA_OPTS`替换：

```sh
JAVA_OPTS='-Xms16m -Xmx256m -XX:MaxDirectMemorySize=128m' ./tunnel server -c state/server.properties
```

自签名证书适合自部署起步，客户端通过显式信任`server.crt`校验服务器。生产证书可在配置中替换为自己的证书和私钥；初始化证书有效期365天，需要自行续期。

此版本已有多协议实测，但存在TCP半关闭、UDP空报文等已知边界；不要把快速启动包当作长期稳定性已验证的正式承诺。

## 维护者：构建与发布

```sh
mvn package
python scripts/build_release.py                  # target/release/tunnel-java.zip
python scripts/build_release.py --runtime        # 当前平台的免安装Java包，需JAVA_HOME指向Temurin等开源JDK17+
python scripts/verify_release.py                 # 验证解压包、启动和初始化
```

打包采用文件白名单，只包含JAR、启动器、示例配置、快速启动说明及可选运行时；不归档整个工作区，不带真实令牌、私钥、诊断数据或压测记录。每个包附带SHA-256文件。

`.github/workflows/release.yml`在手动触发或推送`v*`标签时构建Linux amd64、Linux arm64、Windows amd64包，并运行集成检查。标签必须与`pom.xml`版本一致。推送标签后生成GitHub Release**草稿**，供检查产物和说明后再公开。

以当前0.4.0为例，提交并推送所需改动后，发布流程是：

```sh
git tag v0.4.0
git push origin v0.4.0
```

上述命令会触发远端构建，不是下载者的安装步骤。只应在确认版本、待发布提交和已有标签后由维护者执行。手动触发只上传Actions构建产物，不创建公开Release。

公开Release后，固定文件名使`releases/latest/download/...`链接可用于后续版本。需要固定版本时使用`releases/download/v0.4.0/...`。升级时先备份配置和凭据，再在新目录解压并指向原配置。

GitHub官方说明：[Release下载链接](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)。
